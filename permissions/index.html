For users and Google Play review

Studic is a user-initiated focus timer. You choose Normal, Deep or Scheduled, you choose how long, and you can uninstall at any time when a session is not running. Permissions exist only so those modes can work as you asked.

  • Normal mode needs notifications only. It does not block apps and does not lock the phone.
  • Deep and Scheduled need extra permissions, asked in a short one-time setup the first time you use those modes.
  • Auto-lock during focus is a Settings switch (on by default). You can turn it off. When it is off, Studic still brings the timer back if you leave, but it does not lock the screen.
  • Hide system notifications is off until you grant Notification access. It only runs during a session you started.
  • You can turn any permission off in Android Settings. Deep and Scheduled then pause until you turn it back on.

What Studic never uses

These are listed so a Play reviewer can match the APK. Studic does not include or request:

  • Accessibility Service (no BIND_ACCESSIBILITY_SERVICE)
  • Device Owner, work profile, kiosk mode, or enterprise MDM
  • Screen pinning / startLockTask()
  • Permission to wipe the phone, change the lock-screen password, factory reset, disable the camera, or watch installed apps as an admin
  • A permanent uninstall block. You uninstall from Settings → Uninstall Studic (turn Device admin off there first if Android asks)
  • Contacts, SMS, call logs, camera, microphone, precise location, or full storage access
  • Reading the body of other apps’ notifications to advertise or to send off the phone
  • A Studic account or Studic server. Session, points and settings stay on the device unless you export a backup file yourself

Screen lock — you control this

During a Deep or Scheduled session you started, if you leave the timer or open an app that is not allowed, Studic brings the timer back to the front.

Separately, Studic can lock the phone at that moment, the same way the power button locks it. That uses Device admin’s lock-screen only policy (see Device admin).

  • The switch is Settings → Auto-lock during focus.
  • It is on by default so a strict session is harder to walk away from.
  • You can turn it off any time. Studic then still returns you to the timer, but it will not lock the screen.
  • Normal mode never locks the phone.
  • Locking does not change your PIN, pattern or password. Unlocking works with the same lock you already set on the phone.
If Auto-lock is off, Device admin is still part of Deep/Scheduled setup because the lock feature is available when you turn the switch back on. You can also deactivate Device admin in Android Settings; Deep and Scheduled then cannot start until you enable it again.

Notifications

Asked at first launch

Android: POST_NOTIFICATIONS

Why Studic asks

To show the remaining session time, a notice when a scheduled session cannot start, and an occasional quiet reminder if you have not focused for a few days.

What it does

  • Session timer on the lock screen / shade while you focus (you can turn this channel off in Settings → Notifications Manager)
  • “Schedule skipped” if a window cannot start because of points
  • A history-based focus reminder (no Settings row; only after you have completed sessions)

What it never does

  • Sales, promotions or spam
  • Notifications from other apps (that is a different, optional permission below)

If you turn it off

Studic still works. You may miss the timer, skip notice and reminder. You can allow notifications again from Notifications Manager or Android Settings.

Usage access

Deep & Scheduled

Android: PACKAGE_USAGE_STATS (Usage access)

User-facing purpose

This is the core of strict focus: Studic needs to know which app is currently on screen so that, during a session you started, only your chosen study apps (plus Phone and Messages) stay available, and other apps are closed.

What Studic uses

  • The foreground app’s name / package during an active Deep or Scheduled session, so allowed apps stay and other apps do not
  • On Home, after you have granted Usage access, an on-device app usage chart (Today / This week / Last week). Totals are computed on the phone from Android usage events. Studic does not upload that chart

What Studic never does

  • Read messages, emails, passwords, or anything you type or see inside another app
  • Record browsing history or a permanent log of every app you open for advertising
  • Send package names to a Studic server (there is none)

Normal mode does not require Usage access. You can revoke it in Android Settings → Apps → Special app access → Usage access. Deep and Scheduled cannot run until it is granted again.

Device admin

Deep & Scheduled

Android: Device Administration API, policy force-lock only. Receiver: BIND_DEVICE_ADMIN. XML: force-lock. No wipe, password, or other admin policies.

Used only to lock your screen when you leave a Deep or Scheduled session. Studic cannot read your private information, erase your phone or change your password.

User-facing purpose

When you start a Deep or Scheduled session and then leave the timer or open a blocked app, Studic can lock the screen (the same action as the power button) so that when you unlock, you are back on the timer. This only happens if Settings → Auto-lock during focus is on.

What the admin policy is allowed to do

  • Call the system lock-screen API (lockNow / FORCE_LOCK) during a user-started Deep or Scheduled session, and only when Auto-lock is enabled

What it is not allowed to do (and the app does not request)

  • Read your private information, files, messages or passwords
  • Erase the phone, factory reset, or wipe app data as an admin
  • Change, reset or see your PIN, pattern, password or biometrics
  • Disable the camera, watch which apps you install, or enroll the phone as Device Owner / work profile / kiosk
  • Prevent uninstall. You can deactivate Device admin and uninstall Studic from Settings → Uninstall Studic or from Android’s app info screen when no strict session is running

User control

  • Turn Auto-lock during focus off: no screen lock; timer still returns to the front.
  • Deactivate Device admin in Android Settings: Deep and Scheduled cannot start until you enable it again. Normal mode is unchanged.

Studic is not a device-management, parental-control or anti-theft product. Device admin is used only as a lock-screen helper for a study session the user started.

Display over other apps

Deep & Scheduled

Android: SYSTEM_ALERT_WINDOW

User-facing purpose

If the phone restarts while a Deep or Scheduled session is still running, Android may not allow a normal activity to appear on the lock screen. Studic then shows a short recovery screen (about 5 seconds) so you can continue the session you already started. This is not a daily blocking overlay and it is not shown in Normal mode.

What it never does

  • Draw ads, spam, or a permanent layer over other apps
  • Read or capture what other apps display
  • Replace Android Settings or hide the uninstall button

You can revoke overlay in Android Settings. Strict sessions can still run until a reboot; recovery after restart needs this permission.

Background / battery (ignore optimizations)

Deep & Scheduled

Android: REQUEST_IGNORE_BATTERY_OPTIMIZATIONS

User-facing purpose

Many phones stop background apps to save battery. If that happens mid-session, the timer and app blocking can pause. Allowing Studic to run without those restrictions keeps a session you started running until it ends, and helps scheduled windows start on time.

What it never does

  • Run hidden work when you are not focusing or have no schedule
  • Collect or send personal data in the background

Notification access (hide other apps’ notifications)

Optional — off by default

Android: BIND_NOTIFICATION_LISTENER_SERVICE. Service used only to dismiss shade notifications, not to display a second notification inbox.

User-facing purpose

An optional focus aid, like putting the phone on a quiet mode for other apps. In Settings → Notifications Manager, you can turn on Hide system notifications. Android then opens the Notification access list. You choose Studic and allow access.

Only while a session is running, Studic dismisses other apps’ status-bar / shade notifications so chats and mail are less likely to pull you away. Study apps (and break apps during a break) are left alone. Studic’s own posts stay. Ongoing, alarm and call notifications are not dismissed.

What it never does

  • Read notification text or titles for advertising, analytics or training
  • Send notification contents off the device
  • Run when no session is active, or after you turn the switch off
  • Replace Android’s notification shade or act as a notification backup product

Revoke Notification access in Android Settings, or turn the switch off in Notifications Manager. Normal, Deep and Scheduled still work without it.

Alarms and reminders

Scheduled mode

Android: SCHEDULE_EXACT_ALARM

Lets a study window you created start at the time you set, and lets a quiet focus reminder fire at your usual start hour. Not used for ads. If Android asks you to allow alarms and reminders for Studic, that is this permission.

Run at startup

Deep & Scheduled recovery

Android: RECEIVE_BOOT_COMPLETED (including locked-boot)

If the phone restarts during a Deep or Scheduled session that was already running, Studic can restart its protection and show the short recovery screen. It does not start a new session from a reboot by itself. Normal mode does not use this for a lock overlay.

Foreground service (special use)

While a session or recovery is active

Android: FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE

Keeps the session timer and protection running while you focus, and runs the short boot-recovery screen if needed. Android requires a visible foreground service for this kind of work. The user-visible reason is: strict focus session protection and reboot recovery. This is not a hidden tracker.

Keep the device awake (briefly)

Android: WAKE_LOCK

Lets alarms and the session service run on time. It is not used to keep the screen on against your will.

Know if the screen is locked

Android: DISABLE_KEYGUARD (legacy name). Studic uses Keyguard APIs to detect whether the lock screen is showing.

This lets recovery and leave-handling wait until you unlock with your own PIN, pattern or biometrics, then show the timer. Studic does not remove your lock screen, does not learn your PIN, and does not bypass unlock.

Internet (from Google libraries, not a Studic server)

Studic does not ship its own backend. The app can reach the network when you:

  • Watch a rewarded ad (Google AdMob, with UMP consent where required)
  • Buy or restore a points pack (Google Play Billing)
  • Open Privacy, Terms, Help or this page inside the app

Those libraries add their own network permission. Ads may use an advertising ID under Google’s policies. Pro users do not see ads. Details: Privacy Policy — Ads.

Phone-maker auto-start (not an Android permission)

Some brands (for example Xiaomi, Oppo, Vivo, Huawei, Samsung) have an extra switch that can stop apps after you leave them. Studic cannot read whether that switch is on. The one-time setup may ask you to open that screen and turn Studic on, so a session is not killed in the background. If your phone has no such screen, skip it.

How to turn permissions off

  1. In Studic: Settings → Permissions Manager (status of Usage access, Device admin, overlay, battery, notifications) and Settings → Notifications Manager (session timer, hide other notifications, schedule skipped).
  2. Auto-lock: Settings → Auto-lock during focus (on or off; default on).
  3. In Android Settings: Apps → Studic, or Special app access, for Usage access, Device admin, Display over other apps, Battery, Notification access, and Alarms.
  4. To remove Studic: Settings → Uninstall Studic. Android may ask you to turn Device admin off first. That is expected and allowed.

Notes for Google Play review

Package: com.amirsofteng.studic. Category: productivity / focus (digital wellbeing). All sensitive access is tied to a session the user starts, or to an optional switch the user turns on.

Device admin
FORCE_LOCK / lockNow only, during a user-started Deep or Scheduled session, and only if Auto-lock is enabled. Not Device Owner. Not wipe. Not password. Not anti-uninstall.
Usage access
Foreground app during that session so allowed study apps stay available. Also powers an on-device Home usage chart after grant. No off-device app-graph.
Display over other apps
Short reboot-recovery UI if a strict session was already running. Not a daily overlay. Not ads.
Notification access
Optional. Off until the user enables Hide system notifications. Dismisses other apps’ shade posts only while a session runs. Does not upload notification content.
Foreground service (special use)
Visible session protection and reboot recovery, declared in the manifest property.
Accessibility
Not in the app. Not used as a fallback for blocking.
